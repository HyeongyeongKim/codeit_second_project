# RFP 문서 검색·답변 실험

공공 입찰 제안요청서에서 질문의 근거를 찾고 답하는 RAG 시스템의 실험 기록입니다. **실험을 바꾼 이유 → 바꾼 방법 → 확인한 결과 → 다음 변경 이유**를 읽으려면 [실험의 의사결정 흐름](EXPERIMENT_JOURNEY.md)부터 보세요. [Notion 문서 9개](https://app.notion.com/p/3ec67f3920118072b687d3aaed1e4428)와 노트북·실행 기록을 대조했고, 실행 결과와 계획을 구분했습니다.

## 주요 흐름

1. PDF 한 파일로 일반 질문·HyDE를 탐색한 뒤, HWP/PDF와 Markdown 표 추출을 적용해 RFP 전체 문서로 확장했습니다.
2. OpenAI 임베딩(`text-embedding-3-small`)과 GPT-5 mini 생성을 시험했습니다. 이어 Hugging Face 기반 경로에서 Dense + BM25 + RRF + 재순위화로 근거 검색을 개선했습니다.
3. 고정 평가 질문과 검색·답변 평가를 만들었습니다. 전체 문서에서 다른 사업의 청크가 섞이는 문제를 발견해 **사업 식별 후 해당 사업만 검색**하도록 바꾼 것이 가장 뚜렷한 개선이었습니다.
4. 정제, 700/100 대 1000/200 청킹, 임베딩 모델, 기본 대 Kiwi BM25를 차례로 비교했습니다. 일부 평균 점수는 채점 변동이나 같은 최종 문맥 때문에 단독 원인으로 해석할 수 없습니다.
5. 30문항에서 Kiwi BM25는 **단독 검색 Recall@20 0.8273**으로 기본 **0.6365**보다 높았지만, 별도 GPT 답변 평가 평균은 기본 **0.7967**, Kiwi **0.7300**이었습니다. 검색 지표와 답변 점수는 분리해 읽어야 합니다.
