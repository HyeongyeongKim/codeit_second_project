# codeit_second_project

RFP 문서 질의응답(RAG)의 문서 전처리, 검색, 답변 생성, 임베딩 모델을 평가한 기록입니다.

전체 실험 순서와 임베딩 비교는 [RAG 실험 기록](RAG_실험_기록.md)에, 초기 실험의 문항별 분석과 설정은 [10월 8일 상세 보고서](2026-10-08_RAG_상세_보고서.md)에 정리했습니다.

## 지금까지 확인한 내용

- 문서 정제: NFC 정규화, 깨진 글머리기호·단독 쪽 번호·목차·빈 표 줄 제거를 시험했습니다. 답변 품질 개선은 입증되지 않아 현재 주력 설정에서는 제외했습니다.
- 답변 생성: `gpt-5-mini-2025-08-07`로 변경했지만 검색 실패가 남았습니다.
- 검색: 최종 문맥을 4개에서 6개로 늘리는 과정에서 다른 사업의 문서가 섞이는 문제를 찾았습니다. 질문의 사업명을 식별하고 그 사업 문서로 검색 범위를 제한하자 성능이 크게 개선됐습니다.
- 청킹: `700/100`에서 `1000/200`으로 바꿔 보았으나 뚜렷한 우위는 확인되지 않았습니다.
- 임베딩: 기본 Alibaba 모델, `BAAI/bge-m3`, `dragonkue/BGE-m3-ko`, `nlpai-lab/KURE-v1`을 비교했습니다. 한 사업 10문항에서는 dragonkue 모델의 Factual Correctness 평균이 가장 높았지만, 추가 검증이 필요합니다.

점수는 한 사업의 첫 10문항 평가 결과입니다. 전체 15개 사업, 180문항의 성능으로 일반화하지 않습니다.
